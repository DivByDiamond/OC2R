# Генерация ресурсов

Для NeoForge 26.1.2 и 26.2 клиентские и серверные генераторы запускаются отдельно:

```sh
./gradlew :26.1.2:runClientData :26.1.2:runData
./gradlew :26.2:runClientData :26.2:runData
python3 scripts/verify-datagen.py
```

Каждая версия использует собственные каталоги `versions/<version>/build/generated/datagen/client` и `server`. Раздельные каталоги нужны потому, что Minecraft удаляет устаревшие результаты providers в рамках одного каталога. Запуск серверного генератора сохраняет клиентские результаты и наоборот.

Следующая задача `processResources` накладывает оба набора на ресурсы этой версии после преобразования совместимых ресурсов 1.21.1. Исходные общие ресурсы остаются базой для вручную написанных рецептов и геометрии блоков. Обычная сборка работает и без предварительного datagen.

Клиентский provider генерирует 144 JSON: 63 модели предметов, 63 определения предметов 26.x, 17 blockstates и геометрию монитора для отображения предмета. Во время генерации проверяется покрытие фактически зарегистрированных предметов и блоков OC2R. Регрессии сравнивают повороты, подключения шины, отображение предметов и tint с используемыми ресурсами.

Серверные providers генерируют loot, теги и 40 рецептов с advancement-данными; остальные 20 рецептов проекта пока написаны вручную и сохраняются при упаковке. Результаты компьютера и робота используют `ItemStackTemplate`, чтобы включать прошивку до привязки компонентов предметов Minecraft.

Проверено 2026-10-18: оба клиентских и оба серверных запуска завершились успешно. Каталоги каждой версии содержат 144 клиентских и 111 серверных JSON. Генерация 26.x не записывает файлы в общие `src/main/resources` или `src/generated`.
