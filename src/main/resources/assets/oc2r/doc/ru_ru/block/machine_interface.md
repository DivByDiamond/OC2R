# Машинный интерфейс
![Machine interface](block:oc2r:machine_interface)

Машинный интерфейс связывает программу с механизмом перед своей соединительной стороной. У него есть предметный буфер, хранилища энергии и жидкости. Компьютер получает доступ через интерфейсную шину.

Название устройства в API: `machine_interface`. [Рецепт блока](https://wiki.loki-code.dev/ru/recipes#recipe-machine_interface).

## Первый вызов

```lua
local m = assert(require("devices"):find("machine_interface"))
print(m:getTargetBlock())
print(m:getTargetSlotCount())
```

Установите интерфейс соединительной стороной к целевому механизму. Доступ зависит от того, какие операции механизм разрешает с этой стороны. Отсутствие нужного обработчика вызывает ошибку, а не создаёт доступ к закрытому инвентарю.

## Предметы

В окне блока 18 обычных слотов с номерами 0–17. Ещё один служебный слот, 18, удерживает предметы, которые не удалось вернуть при переносе. Пока там есть остаток, сначала выполните `recoverItems()`.

| Метод | Назначение |
|---|---|
| `getTargetSlotCount()` | Число слотов механизма |
| `getTargetItem(slot)` | Содержимое слота механизма |
| `getBufferItem(slot)` | Содержимое своего буфера |
| `pushItems(bufferSlot, targetSlot, amount)` | Из буфера в механизм |
| `pullItems(targetSlot, bufferSlot, amount)` | Из механизма в буфер |
| `recoverItems()` | Вернуть удержанные остатки в обычный буфер |

Методы переноса возвращают фактическое число предметов. Нумерация слотов начинается с нуля.

## Жидкости и энергия

`getEnergyStored()` и `getFluidStored()` читают собственные хранилища. Для механизма есть `getTargetEnergyStored()`, `getTargetTankCount()` и `getTargetFluid(tank)`.

`pullEnergy(amount)` и `pullFluid(amount)` забирают ресурс из механизма. `pushEnergy(amount)` и `pushFluid(amount)` отправляют его из буфера в механизм. Проверяйте возвращённое количество. `recoverFluid()` обрабатывает удержанный остаток жидкости.

## Состояние и настройки

`getTargetBlock()` возвращает ID блока. `getTargetState()` возвращает свойства его состояния. Поддерживаемые механизмы Create также предоставляют `getSettings()` и `setSetting(id, value)`.

Это доступ к явно поддерживаемым настройкам. Произвольный NBT механизма интерфейс не выдаёт. Для блока без подходящего API настроек вызов завершится ошибкой.
